## Prospective operationalizations (agent-added, not original human preregistration)

These fill unspecified execution details and are frozen in Git **before any calibration outcome**. They do not amend scientific features or targets.

1. Error scale is the median absolute selected P6 OOF error (all fitting records, no trimming). Delta multipliers are exactly [-2,-1,-.5,0,.5,1,2].
2. Service unit u is median P6 fitting-only C0 L_ref across center/seeds. Normalize every service/assessment loss by u. Maintenance event cost is .10 normalized units, RI event cost is ratio*.10 for ratios [2,5,10]. Primary ratio is the middle convention 5, fixed independently of all method outcomes. Report all three ratios and select parameters separately within each, never compare incomparable weighted objectives to pick a favorable ratio. In raw units lambda_M=.10u and lambda_R=ratio*.10u. Costs count accepted intervention events; copied probes/search work are separately measured, not secretly treated as zero compute.
3. Primary false escalation means **actual RI on oracle-recoverable stages**, denominator all stages with finite-policy R>=0 on that method's pre-action incumbent. Missed escalation means no actual RI on R<0, denominator all R<0 stages. False gate opening and missed gate opening are also reported with the same oracle denominators. Negative R does not guarantee a feasible/better alternative; report that limitation without deleting any target-negative denominator. Rates are computed within center (pooling paired seeds/scenarios), then macro-averaged over defined centers; denominator-zero rates are null, not zero. Counts and numbers of defined centers accompany conditional rates. No scenario-label ground truth.
4. Primary select Proposed by macro-center J_life subject to macro-center false actual-RI <=.10. Secondary .05. Tie: lower actual RI rate, lower search rate, lower delta, config ID. Fallback is not added to the seven-candidate grid. Baselines select minimum macro J_life within method/ratio without Proposed's gate constraint; tie lower RI/search then lexicographic config ID.

## Implementation changes

P7 uses new `core/p7.py`, `scripts/run_p7.py`, `tests/test_p7.py` and P7-only configs/artifacts. Existing manifest-bound P6 files and repositories 1/2 are not edited. River 0.23.0 was installed into the existing Python environment using `--no-deps`; runtime version is pinned and checked. Available RAM was about 2.75 GB, so the executor defaults to one worker (each uses the existing two torch threads) and final analysis streams one center at a time; no center/configuration is removed. Completed trajectory CSVs have immutable hash receipts and can be resumed without estimator refitting or changing decisions. Raw outcomes are SHA-bound by the final manifest; protocol, selected parameters, metrics and freeze evidence are Git-committed without adding unrelated historical untracked files. Additional procedural recovery changes, if any, must be recorded in a separate recovery MD because this pre-outcome protocol itself is immutable after binding.
